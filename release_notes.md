## Unreleased (x3d-blender-io fork)
- **The node board's second batch: Switch, LOD, IndexedTriangleSet and PixelTexture are written back** (docs/NODE_BOARD.md; `tests/test_node_board_batch2_bpy.py`, fixture `tests/node_board/gap_batch_2.x3d`). (1) **Switch and LOD.** The import records the Switch and LOD nodes above every object it makes (`x3d_group_chain`, JSON, outermost first: DEF or a made-up key, branch, branch count, and whichChoice or range and center), on Transform empties too; the X3D 4.0 writer gathers siblings into those nodes again, every branch and level in place (an empty one as an empty Group, so whichChoice counts the same children). Before, the Switch dissolved (its other branches were written `visible="false"`) and the LOD levels the first Viewpoint does not see were not written at all. A ROUTE into `Switch.whichChoice` now lands on a Switch in the file (it was dropped). No DEF is made up for a Switch the file did not name. (2) **IndexedTriangleSet.** A mesh read from one (`x3d_geometry` on the mesh), or any mesh when the export triangulates, is written as one while every face is a triangle, else as an IndexedFaceSet. (3) **PixelTexture.** An image read from one (`x3d_pixel_texture`, its component count) is written back inline, pixel for pixel, up to 256 x 256; it was lost (no file to point at). (4) A primitive DEF no longer gains a second `GE_` on every round trip, so importing the export and exporting again writes the same file. Limits: LOD center and range are kept in the file's units (right when the import and export scales match); a GeoLOD is not written back.
