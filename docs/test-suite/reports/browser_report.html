Z00 Document, header, world and integrity

  • X3D 4.0 document header
    A well-formed XML file whose root is <X3D version='4.0' profile='Immersive'> with the X3D 4.0 DOCTYPE and a <head> that declares component Shape level 2 (PhysicalMaterial needs it) and a generator <meta>.
  • X3D 4.1 draft document header
    Same file written with version 4.1: root version='4.1' and the 4.1 DOCTYPE.
  • NavigationInfo mirrors the scene lighting
    The scene contains Blender lights, so NavigationInfo must switch the headlight OFF (headlight='false') or the scene would be double-lit; navigation type lists EXAMINE.
  • World colour becomes Background skyColor
    The world's Background node colour x strength (0.10 0.20 0.40 x 0.5) appears as <Background skyColor='0.05 0.1 0.2'>. A decoy 'viewport colour' is set on the world to a different value to prove the exporter reads the node tree.
  • Geometry reuse is reported in the head
    Because many objects share a mesh, a <meta name='info'> says 'Reused geometry (DEF/USE)'.
  • File parses as XML
    No XML syntax errors, no duplicated attributes, UTF-8.
  • Every DEF is unique
    No two nodes share a DEF name (X3D requires scene-wide uniqueness).
  • Every USE resolves to an earlier DEF
    Each USE='x' names a DEF that appears EARLIER in document order (X3D forbids forward references).

Z02 Normals, smoothing and creaseAngle

  • Flat cube: one normal per corner, axis-aligned, unit length
    <Normal vector=...> present with one unit vector per Coordinate; each is +/-X, +/-Y or +/-Z; no creaseAngle.
  • Smooth sphere: interpolated normals pointing away from the centre
    Normals are unit length and (for a sphere centred at the origin) parallel to their vertex positions; browser: smooth shading, no faceting.
  • Custom split normals are exported (Blender 4.1+)
    All normals equal (0,0,1) although the sphere is smooth: browser shows a sphere lit like a flat disc (top bright, uniformly shaded).
  • Normals stay in object space under rotation and negative scale
    Normals are written in local space; the Transform (rotation + mirrored X scale) carries the rest. Radial test on the cone's rim: still consistent with positions in local space.
  • Without explicit normals a flat mesh has creaseAngle 0
    Export option 'Normals' OFF: smooth/flat intent is carried by creaseAngle. Flat cube -> attribute absent (default 0).
  • Without explicit normals a smooth mesh has creaseAngle pi
    Smooth sphere -> creaseAngle='3.141593' (full smoothing). Browser computes the normals itself.
  • With explicit normals the mixed sphere is exact
    Main profile: normals preserve the hard edge between the smooth upper and flat lower hemisphere (more distinct normals than a purely smooth sphere would give at the equator seam).

Z03 UV sets, seams and vertex colours

  • UV seams split vertices, arrays stay parallel
    The cube's cross-shaped UV unwrap needs more than 8 Coordinates (vertices are duplicated along seams); TextureCoordinate has exactly as many entries as Coordinate; coordIndex indexes all of them.
  • Mesh without UVs: no TextureCoordinate node
    No TextureCoordinate element is written (an empty or fabricated one would break X_ITE texturing).
  • Only the ACTIVE UV map is exported
    TextureCoordinate holds the values of the layer named 'Second' (e.g. 0.125 0.875), not the default 'UVMap'.
  • Per-vertex float colours with alpha -> ColorRGBA
    <ColorRGBA color=...> with one RGBA entry per Coordinate; alpha 0.75 everywhere; values are Blender's linear floats verbatim. Browser: a red/green gradient plate (the colours multiply the base colour in X_ITE).
  • Per-face (corner) colours split vertices
    Each cube face has its own flat colour, so the 8 positions become >= 24 Coordinate entries with 24 matching colours; browser: a six-coloured cube.

Z07 Beyond scalar PBR: Principled extras and non-Principled shaders

    Z08 Transforms, hierarchy and parenting

    • Five-deep parent chain keeps world transforms
      Each Transform is nested in its parent's Transform (hierarchy mode) and the composition of translation/rotation/scale up the chain equals Blender's matrix_world after the Y-up conversion. Browser: a gently rising spiral of five cubes.
    • Hierarchy export nests Transforms; flat export does not
      Main profile: chain1 is a direct child of chain0, etc. 'crease' profile (Hierarchy OFF): every Transform is top-level (world matrices) yet world poses are still right.
    • Flat (non-hierarchical) export keeps world transforms
      Hierarchy OFF: all five cubes are top-level Transforms with baked world matrices.
    • Skew from non-uniform parent scale survives in hierarchy mode
      Parent scale (2,1,1) with a child rotated 45 deg produces a sheared world matrix. Nested TRS Transforms reproduce it exactly.
    • All rotation modes (Euler orders, quaternion, axis-angle, gimbal pole)
      Whatever the rotation mode, the Transform rotation equals the object's actual orientation (axis-angle in X3D space). Includes a 90 deg gimbal-lock pitch.
    • Mirrored (negative) scale
      Negative scales are written as such (X3D allows them); the composed matrix equals Blender's, including a full inversion (-1,-1,-1).
    • Delta transforms and a non-identity parent-inverse matrix
      Both are baked into matrix_world by Blender and therefore into the exported Transforms.
    • Vertex parenting and Track-To constraint resolve to world matrices
      matrix_world already contains the constraint / vertex-parent result, so both objects land exactly where Blender shows them.

    Z11 Lights: type mapping, intensity, spot cone, direction

    • Point light: colour, intensity mapping, custom range
      <PointLight color='1 0.8 0.6' intensity='0.571429' radius='8' global='true'> inside the object's Transform; location 0 0 0 (the Transform places it). intensity = min(energy_watts / 1.75, 1).
    • Very bright point light clamps to intensity 1
      1000 W -> intensity 1.0 (SFFloat intensity is limited to [0,1]).
    • Spot light: cone angles and range
      <SpotLight beamWidth='0.387463' cutOffAngle='0.503702' direction='0 0 -1' radius='9.2587'> (legacy-exporter formulae: beamWidth = size x 0.37, cutOffAngle = 1.3 x beamWidth). intensity 0.875/1.75 = 0.5.
    • Sun -> DirectionalLight with world direction
      <DirectionalLight direction='0 0 -1' intensity='0.6' global='true'> in a Transform that rotates it; the WORLD direction (Transform rotation applied to the local -Z) equals Blender's light direction after the Y-up conversion.
    • Sun strength above 1 clamps
      strength 3 -> intensity 1.
    • Area light -> DirectionalLight (documented approximation)
      X3D has no area light; the exporter maps it to a DirectionalLight along the lamp's -Z. Expect a DirectionalLight with the right world direction (no crash, no PointLight).
    • Every light is global
      global='true' on all lights: lights inside a Transform would otherwise only light their siblings (nothing).

    Z13 Animation: sampled transforms, hierarchy, constraints, drivers, physics

    • One TimeSensor drives everything
      <TimeSensor DEF='SceneTimer' cycleInterval='2.000000' loop='true'>: frames 1..49 at 24 fps = 2.0 s. Browser: animation starts by itself and loops seamlessly.
    • Keyframed translation (linear, 3 keys)
      A PositionInterpolator with one key per frame (49 keys, 0..1) routed TimeSensor.fraction_changed -> set_fraction and value_changed -> Transform.set_translation. Browser: the cube glides left->right rising to the middle and sinking again.
    • One full revolution (OrientationInterpolator)
      49 orientation keys; angular velocity constant, so even mid-frame playback positions match Blender. First and last orientation are identical (seamless loop).
    • Scale pulse
      A scale interpolator (PositionInterpolator DEF SI_*) routed to set_scale.
    • Bezier-eased motion is sampled, not approximated by two keys
      Because every frame is sampled, the ease-in/ease-out curve survives: mid-timeline positions match Blender (not a straight line).
    • Animated parent with animated child (orbit + bob)
      Parent rotates (orientation interpolator), child bobs (position interpolator) in parent space; composed world position equals Blender's at every sample frame. Browser: a cube circling its pivot while bobbing.
    • Constraint-driven object animates without own keyframes
      Z13_follow has no keys, but follows Z13_move through a Copy Location constraint: the exporter samples matrix_world, so it still receives an interpolator.
    • Driver-based animation (rotation = frame x 7.5 deg)
      Drivers are evaluated by Blender before sampling, so Z13_driver turns 360 deg over the cycle.

    • 4.0 export degrades splats to a coloured PointSet
